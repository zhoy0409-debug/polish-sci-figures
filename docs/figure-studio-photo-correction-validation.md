# 照片校正开发验收报告

**更新日期：2026-10-19。状态：本地浏览器功能验收通过；大图性能仍有限制，Windows 安装版尚未验收；尚未发布，正式安装包仍为 0.1.25。**

本报告供维护者和试用者核对一键矫正、四角微调、标尺拉正及一键校色的实际验证范围。操作步骤见[照片校正使用说明](figure-studio-photo-correction.md)。本轮复用原画布合成、原图显示、预览事务、工程历史与导出逻辑，未修改科研计算后端。

## 交付内容

代码位于 `skills/polish-sci-figures/assets/figure-studio/`：`image-rectify.js` 提供真实像素投影重采样及记录验证，`image-rectify-detect.js` 提供本地边缘建议，`image-straighten.js` 提供两点标尺几何，`image-rectify-ui.js` 提供统一预览与微调。已有 `image-color.js`／`image-color-ui.js` 增加照片自动显示建议。

自动化用例、完整页面浏览器脚本和 CI 接线随源码提供。私有照片、含原图工程、导出图、截图和失败记录仅保留在本机 `.cache` 中，不随仓库或安装包分发。

本轮可分发的[脱敏验收摘要](qa/photo-correction-20261019.json)记录实际页面与脚本哈希、逐组结果、时序和未验证范围；不包含原图或私有工程。

## 真实照片与浏览器操作

使用用户授权的一张 5712 × 4284、8,877,458 字节的倾斜屏幕照片进行本地工程验证；另一张组图只作参考。照片没有独立的检测真值标注。实际浏览器提出 5 个边界，首个候选覆盖较大的应用／显示区域，不能直接视为胶图内容框；内部胶图区未可靠识别，需要切换或手调。没有据此计算检测准确率、漏检率或误报率。

首轮整页诊断使用 Chrome 155，7 组实际操作通过：普通文件导入、主画布投影预览、无效草稿保留最后有效视图、取消／迟到结果、一次保留及撤销重做、工程确认后保存重开、原图版本切换和从原始字节再次调整，以及后续颜色编辑。主画布草稿期间，project、state、history、checkpoints、dataDrafts 五个保存容器均未改变。校正后的实际 SVG、PNG、TIFF 已导出；PNG／TIFF 独立解码像素一致，Carbon／Pearl 两主题导出一致。原始 JPEG 字节未变。此轮是增加自动建议最终排序和标尺之前的接线诊断，不能代替新增功能的最终整页验收。

诊断页面没有浏览器错误、外网请求或图像载荷外发。操作截图与私有导出图已实际查看；不将 headless 浏览器结果称为已安装 Windows 应用验收。

最终冻结页面在 Chrome 155.0.8059.82、1440 × 1000、DPR 1 的独立浏览器中完成 **11／11 组真实操作**。自动建议、重复自动操作、后续一键校色、颜色微调、荧光模式禁用、篡改工程拒绝及以上全部事务／导出路径通过。先应用颜色、再拖标尺的预览和保留均精确继承原参数；原图版本没有烘焙调色，编码字节保持一致。真实鼠标参考线计算为 −0.8573984089764641°，整体旋转 +0.8573984089764641°，输出 3315 × 1741，统一像素步长 1，无外部填充。该参考线为明确的人工选取，不是独立物理标定。

最终示例工程保存后通过普通“打开工程”确认路径重开，原始 JSON 字节一致。本机还制作了已载入原始照片的可编辑示例页面和实际操作截图序列动图；示例页再次在真实浏览器中验证中文、一键预览、标尺入口和取消恢复，零页面错误和外网请求。动图由实际步骤截图组成，**不是连续录屏**。

## 发现并修正的问题

记录保留失败和修正的边界，避免把后续通过结果倒写为首次即通过。

- 工程加载起初不检查校正记录；已加入版本、尺寸、角点、H、用途标记及实际编码哈希验证。重复校正的来源版本指针也已指回保留原图。
- 首次主画布渲染抛错时，面板曾提前缓存候选；现仅在渲染成功后保留最后有效结果，并验证失败后的恢复。
- 无效标尺起初可以通过再次点击预览复用旧四角；现会保留旧画面但阻止保留，端点恢复有效后才能继续。几何转换也保留此前已应用的全图显示参数，原图版本继续保留未重采样字节。
- 噪声合成负例曾产生边缘候选；调整启发式门槛后，该工程负例被拒绝。这是开发调参，不能称独立盲测零误报。
- 新增中文状态最初未进入英语字典；已经补齐并通过既有双语覆盖检查。颜色测试首次读取早于真实动画帧完成，改为等待实际 SVG 系数，未放宽产品断言。
- 两次浏览器准备分别因录屏二进制缺失、受限环境无法访问本机端口而结束，均未导入照片；之后使用仅绑定 loopback 的本机服务完成诊断。没有安装网络依赖或虚构录屏。
- 最终首轮脚本在取消后未重新展开图片工具卡片，尝试点击隐藏入口而超时；只修正了脚本的普通导航，在新的证据目录中完整重跑 11 组通过，没有更改产品或降低断言。

## 复现

从源码安装现有 Python 依赖及项目 CI 指定的 JSDOM 后，运行相应 Node 用例；不需要上传图片。

```powershell
node scripts/test_studio_image_rectify.cjs
node scripts/test_studio_image_rectify_detect.cjs
node scripts/test_studio_image_color_auto.cjs
```

真实照片脚本为 `scripts/test_studio_image_rectify_browser.cjs`，要求显式提供原文件、SHA-256、人工四角、服务 URL、对应 HTML 哈希和独立像素解码器，并写入新的私有 `.cache` 目录。脚本只允许指定的 loopback 源，不替换算法结果，不把人工四角当作独立检测标注。CI 中的其余 UI 用例验证迟到、取消、锁和撤销合同。
