# 空白文字分组修复

**更新：2026-10-31。未发布，仍待用户检查。** 本页记录用户反馈“文字内容展开后什么都没有”的原因、改动和实际验证，不替代当前 Windows 安装版及中文输入法验收。

## 原因与改动

原收纳逻辑将旧文字输入框放入“文字内容”，而新版统一编辑器仍在另一个字符分组。选中文字时，统一编辑器会隐藏旧输入框，导致前一个分组展开后为空。修改前的真实浏览器检查得到 `open=true`、可见输入控件为空，且统一编辑器位于别处。[原状态截图](text-content-before-20261031.png)保留复现。

现在复用原有统一编辑器，将内容、字符工具及兼容输入放在唯一的“文字内容与字符格式”分组中，没有复制控制器或输入事件。展开后将该组带入视区。未选中文字时显示禁用输入和选择提示；锁定文字继续受保护。仅在旧非抽屉布局中保留原字符组隐藏规则，避免新抽屉的兼容提示一起被隐藏。

[Carbon 修复后](text-content-carbon-20261031.png)和 [Pearl Pro 修复后](text-content-pearl-20261031.png)来自实际源码 Chrome 页面，使用明确标注的合成 SVG。图片已实际查看，输入和字符按钮可见；不是 Windows 安装版人工操作截图。

## 完成的检查

最终七条受影响 Node 检查通过，包含抽屉唯一归属、层级、富文字、文字几何、宿主／组件输入法事件和人工验收工具合同。生产本机服务／Chrome 九组检查通过；新增文字流程已进入同一个持续检查入口。

新增实际浏览器流程验证了：打开分组可见唯一文字框；从 Control 修改为“实验组”；一次撤销及重做；收起／重开；无选区提示；锁定／解锁；原有 tspan 文本；Carbon／Pearl 与中英文；通过原字符按钮真实加粗并一次撤销。工程原始 SVG、数据草稿及检查点保留，未把显示文字变更当作科学数据变更。最终字符按钮检查另行重跑通过，保留嵌套 tspan 的实际字形样式核对。

[结构化证据与 UI 指纹](text-content-20261031.json)记录上述范围。九组回归还覆盖工程 Worker、原生 TIFF、衍生来源、投稿配置、历史快捷键、抽屉、紧凑窗口及反馈／统计；公开 Iris 和 H&E 流程按原协议保留。不新增速度、原生输入法或独立图像检测准确率声明。

## 保留的失败与边界

初次辅助脚本的相对路径错误、Undo 会清空选区而测试未重新选择、首轮格式断言把外层空 tspan 当作实际字形、随后同一错误断言的超时均保留。最终检查改为观察实际文本节点的父元素，不放宽加粗、来源或一次撤销要求。未修改生产格式算法来迎合测试。

旧源码预览服务已退出；IAB 尝试绑定其错误页时被 URL 策略停止，随后没有继续操作该标签页。本轮采用独立的源码 Chrome 自动化回归和截图检查，不能称为原生接口已修复或 Windows 人工验收通过。历史失败和较早完整批次均保留，最终结果只按最终源资源核对。
