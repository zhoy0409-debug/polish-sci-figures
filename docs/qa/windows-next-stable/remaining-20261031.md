## 本轮修复与证据

Windows显示缩放或缩小窗口后，鼠标／键盘工作区在751–1024 CSS像素范围内曾同时启用桌面抽屉和触控布局。两套工具占用空间，且顶部命令可横向溢出。现在统一750/751断点；触控指针保留原触控工作区，桌面抽屉不同时启用。1100 CSS像素以下命令组换行，保留品牌标记和工程名称。字体搜索为固定标题留出滚动空间，字段和标签可见，不改变图内字体或导出内容。

自动检查使用独立Chrome、公开Iris或明确标注的合成图。1280×720、1024×576、853×480三种CSS窗口分别检查Carbon和Pearl：实际搜索行距／字体、切换选区、收起再展开、边框草稿、取消、下载工程比对。同时检查750、751边界及1024触控指针。DPR为浏览器模拟；这不是Windows系统缩放、安装版实操或普通用户首次查找效率的验收。

[具体检查、布局尺寸及源文件指纹](compact-workspace-20261031.json)保留本轮结果。源码服务的8组回归通过，覆盖工程Worker、原生TIFF及衍生来源、投稿预览／导出、文字历史、抽屉、窄屏及反馈／统计；其中公开Iris 150条观察与公开许可H&E流程均通过。另有4项界面／触控规则和两套主题组件检查通过。原生安装及升级仍按下表保留待验收。

[修改前](compact-workspace-before-20261031.png)可见桌面任务栏和触控工具同时占用空间；[修改后](compact-workspace-after-20261031.png)保留单一工作区。这是源码浏览器截图，选区及搜索字段状态不同，仅用于说明界面布局，不用于声称图形或统计结果发生变化。

持续回归入口为 `scripts/test_studio_drawer_compact_browser.cjs`，已接入生产本机服务／Chrome检查。标准入口：

```powershell
python scripts/run_studio_tiff_browser_checks.py --out <新的验收目录>
```

初轮日志完整保留：执行会话网络隔离、未进入画布的选择失败，以及全局滚动留白导致投稿导出按钮不可达。最后一项通过把留白限定到字体工具修正，不放宽导出断言。测试输出遇旧缓存junction时改用独立目录，没有修改junction。

## 用户体验的五个任务

先在副本工程完成：找到并修改字体／行距；设置对象边框并取消；修改轴刻度并撤销；打开图片校色并取消；找到物理比例尺及标定入口。可以先按分类找，找不到再用Ctrl+K。关注入口是否合理、搜索是否落到正确字段、选区变化是否跳工具、收起后是否保留草稿。

上述流程先用于收集体验问题。当前包的安装实操、中文输入法和真实升级分别记录，全部发布门槛通过且用户重新明确批准后，才合并PR #41并发布。
