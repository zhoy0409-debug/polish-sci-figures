# 已确认方案的 P0 与核心界面改进

用户确认“先修 P0，再统一核心界面”后，按[真实界面审查方案](../../figure-studio-uiux-audit-plan-20261031.zh-CN.md)实施有限修改。继续使用 Carbon Atelier／Mineral Jade 和 Pearl Pro、六类任务与原有科研编辑器。**这是未发布候选，PR #41 保持草稿；不合并、不发布、不部署。**

## 实际改变

| 问题 | 本次行为与验证 |
| --- | --- |
| 局部放大控件误入 44 px 窄栏，遮住工具 | 已归属抽屉的原控件刷新时保留在内容容器。文字→图片→WB→文字、两种主题和中英文均直接点击通过；右侧保持导航与内容两个子项 |
| 英文顶部在 1152 CSS px 溢出 43 px | 现有命令组在中间宽度重排，项目名截断有完整提示，保存、撤销、重做和导出可达。该场景文档宽度恢复为 1152 px |
| 短窗口快捷工具占三排 | 空间不足时将原有导入、框选、边框／图片操作、对齐、锁定和删除快捷入口收入“更多”。字号、加粗、斜体、上下标和颜色留在外部；菜单使用真实原控件，Esc 关闭并恢复焦点 |
| 面板收起后手动视图横移 | 手动倍率保存屏幕锚点，收起／恢复及“专注画布”往返不重新居中。视图边距仅用于编辑器，不写入科学坐标、项目历史或导出；适合窗口仍按空间计算 |
| 属性与检索层级重 | 精简对象／范围提示与折叠组边界，段落组改为“行距、字距与缩进”。检索用分类标题与紧凑命令行，移除每项重复的分类路径；保留方向键、Enter、真实字段焦点和唯一归属 |
| WB 英文同排输入不齐 | 成对字段共用标签行高，Exposure 与膜编号等长短标签的输入上边缘对齐。使用已有颜色、字体与圆角 Tokens，并以轻分隔组织参数，原图与最终预览仍并列 |

“专注画布”位于倍率右侧的四角图标；再次点击恢复之前面板开关状态。输入法／文字编辑不增加全局快捷键拦截。新观察器仅观察工具条宽度，未观察或遍历科研 SVG 的选择热路径。

## 5000 图元性能：保留全部批次

三轮串行 ABBA 共十二批、960 个样本，每项 20 样本、三次预热、250 ms 间隔，测量真实 Chrome 输入事件到第二次 rAF；无录屏／分析器同时运行。基线为 wn21／3c055e6 内嵌源码快照，最终候选按冻结源文件与 HTML SHA 记录。[全部原始样本](uiux-core-20261031/performance.json)保留，没有只挑最快一批。

## 保留的失败与修正

本机 `.cache/uiux-audit-20261031` 与 `.cache/empty-content-20261031/uiux-core-*` 保留全部中间批次：初版“专注”文字按钮让工具条变高，改为有名称／提示的四角入口；空白画布的“更多”向左越界被工程栏遮挡，改为窗口边界内的浮层定位，并通过正常导入复测。旧 TIFF／锁定脚本未打开“更多”，按新真实操作更新；没有删除原来的像素、隐私、锁定或历史断言。

补测还发现主动重开抽屉后“专注”指示未退出，已修复并加入双侧面板与显式退出断言。旧配色测试的强制点击遇到悬停预览正在替换 SVG，改用实际移出预览并普通点击，原失败保留。旧缩放 VM 的宿主、命中适配和函数签名落后于现有源码，接入实际宿主后保留全部缩放／选区坐标断言。大页面截图采集第一次遭 Chrome 响应体缓存淘汰，改用同一本机服务的直接响应计算 SHA；未用旧图填补失败。

## 当前 CI 的英文宽度修正

提交 ec6b42e 的[七项检查通过，真实 Ubuntu 浏览器一项失败](https://github.com/zhoy0409-debug/polish-sci-figures/actions/runs/41182231513)：1440 英文工具条变为 81 px。本机 Windows 的同宽度没有复现；没有放宽高度断言或删去英文场景。次要快捷工具的收纳阈值改为 1200 px 画布宽度，给较长英文／回退字体留出空间，使标准中英文的位置更一致。原 CI 日志和前述全部批次保留，修正后 49 个状态、12 套生产浏览器与四批当前源码性能复测通过，源码和候选重新冻结，等待当前提交 CI；没有追加平台移植。
