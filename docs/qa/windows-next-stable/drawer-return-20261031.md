# 右上角返回与收起：定点交互修复

用户实际体验指出：工具页右上角“收起”隐藏整栏，而真正返回的文字弱化在标题下面，容易让人误以为必须从头找工具。本轮修正这一处导航语义，沿用既有六类工具和原控件；继续保持 PR #41 草稿，不合并、不发布。

| 当前页面／操作 | 本轮行为 |
| --- | --- |
| 字体、边框、校色等具体工具页 | 标题右侧显示有描边与箭头的 **返回**，点击回到同类工具列表，面板保持展开 |
| 返回列表之后 | 自动定位并聚焦刚才的工具；重新进入保留已有字段和手动展开状态 |
| 工具分类列表页 | 右上角才显示 **收起面板**；隐藏时把键盘焦点交回侧边“工具” |
| 侧边“工具” | 随时隐藏／恢复当前页面，不要求从左侧重新开始 |

原先单独一行、不明显的“返回本类工具”已移除。返回使用唯一的原导航按钮，放在固定标题中；正文滚动后仍可操作。没有增加全局快捷键、科研控件、第二份设置表单或历史记录。

## 操作与回归核对

本机独立 Chrome 156 的实际流程包括：进入字体工具、展开批量设置、滚动正文、点击固定标题中的返回、确认面板仍展开和焦点回到字体卡，再进入字体工具；随后从列表收起、由侧边恢复。字体值与折叠状态保留，工程状态和历史未改变。返回也通过键盘 Enter 操作。

边框填入真实预览参数 2 后，返回列表再重新进入，参数保留，保存排除尚未保留的预览；取消恢复原状态。公开 H&E 图片的对比度 1.1 在真实画布预览，返回／重入后保留草稿与滤镜，取消后源图与工程保持一致。原来的 5000 图元改色、一次撤销／重做和保存重开断言继续运行；本轮不据此宣布计时提速。

七项编辑／输入合同与 12 个生产浏览器套件覆盖 TIFF、项目保存、投稿配置、文字、抽屉、反馈与 WB；受影响导航单元检查核对按钮唯一性、归属和焦点。结果见[新旧八场景记录](drawer-return-20261031/navigation.json)及[生产浏览器结果](drawer-return-20261031/production-browser.json)。既有测试中需要“隐藏整栏”的步骤改为真实点击侧边“工具”，保留其草稿、像素和历史断言；返回步骤另外验证面板不能隐藏，没有用强制点击代替可用性验证。
