# 用户主导的科研图形精修：产品原则

本原则来自用户在 2026-10-11 的需求与补充说明。目标是降低不同用户、不同电脑、不同 AI 能力与额度条件下获得满意科研图的门槛。

## 默认闭环

**AI 分析与首版 → 用户直接预览、比较、微调 → 保存选择 → AI 做终稿检查与输出。**

保留全自动路线；用户没有要求手调时，AI 仍可完成全部工作。选择手调时，不要求用户学习复杂口令，也不把每次小改动重新交给模型。

## 必须服务的用户体验

- **即时看到后果**：颜色、透明度等外观参数应本地更新。候选图在当前组图上下文中预览，不能只给抽象名称或无关示意图。
- **先看再定**：试看的状态不覆盖当前选择。用户确认后才记录；撤销、命名版本和原图对照让试错成本足够低。
- **明确改哪里**：选中单元素、同色对象、小图或整图，操作范围必须可见。字体与数据类别不能靠模型猜。
- **把未知选项变得可见**：预览由同一组真实数据生成、且适用的数据表达形式。允许用户根据科学问题和审美选择，不把系统推荐伪装成唯一答案。
- **弥补表达知识差异**：用户不必先知道图形名称。把“适合回答什么问题、比当前形式多展示什么”与真实候选图一起展示。例如将原始点、分布摘要、密度形态和效应量分别可视化，让用户看见只画均值柱形时遗漏的信息。不以新颖或复杂为目标；频数、比例等问题仍可适合柱状图。
- **尽量不耗 AI 额度**：精修阶段在本地浏览器完成；生成新分析与最终科学检查才需要回到 AI / 原绘图工作流。
- **跨环境可交付**：编辑器页面自包含，不依赖作者机器的私有路径或云服务。首版绘图仍需仓库声明的 Python 依赖；字体仍受本机安装情况约束。
- **最后能交回 AI**：保留原图、分析、当前差异和命名版本。AI 接手时检查用户选择，不能直接重跑并抹掉用户的微调。

## 母版应服务证据与叙事

用户进一步要求横版、竖版、加宽版实际预览，规则网格与跨行跨列母版，以及根据文章结构交换小图顺序。母版选择应同时考虑图型、画布比例和整图效果；不能只把同尺寸方块排列整齐。

- **先明确阅读顺序**：由用户确认结果的先后关系；更换母版保留数据身份和已选样式，不按颜色或形状擅自重排科学论证。
- **区分单图与证据组**：显微图及对应定量、条带图及对应统计，可能属于一个证据单元。AI 组图前应确认对应关系，避免因凑齐网格而拆散。不能仅从外观推断对应关系。
- **真实预览帮助选择**：规则对照、横向比较、纵向叙事、上方概览、侧边长图、重点大图分别提供可见候选，不宣称某个母版普遍更好。
- **统一的是视觉秩序**：对齐、留白、字号层级和相关配色协调一致；不同信息密度的面板可以使用不同宽高和跨度。
- **保持科学含义**：画布横竖变化不是交换变量、改变统计量或拉伸图像。图型选择仍由数据和问题决定。

现已实现母版预览、网格、跨格、换位、预生成尺寸候选与可逆状态；证据组整体拖动、自动理解文章叙事、按内容自动评分母版尚未实现。AI 在首稿和终稿环节遵循上述原则，不把规划写成网页现有按钮。

## 技术落点与当前边界

数据/分析、图形资产、外观差异分层存储。已有候选由原 workbench 产生；浏览器只负责可逆外观编辑与组合。当前支持静态 SVG 对象，不把普通 PNG 识别成可无损编辑的数据图。

当前 Figure Studio 使用同一原图上的差异状态实现首稿后手调，工程可交回 AI 检查与导出。尚未实现 AI 实时通过 MCP 控制网页、将全部浏览器差异自动写回 Matplotlib/R 源码、从任意原始数据自动生成新图族。不能将这些规划写成现有功能。

## 借鉴 ILM 的范围

仅参考公开说明中的理念：编辑对象而非扁平图片；布局与原始素材分离；保存可重开的工程；AI 和人类操作围绕共享项目状态。官方 MCP 文档描述的是适配器连接本地 GUI；它解决操作入口，不替代数据模型、渲染器和撤销机制。官方 `.figpack` 文档说明布局与资产可打包携带。
